# Design Ui

Determine product, audience, screen purpose, existing design language, appropriate visual intensity, technical stack and performance budget from the brief and project. Inspect the actual interface and components first; use ui-audit for existing UI and ui-reference for supplied inspiration.

Define visual direction, information hierarchy, layout, typography, component grammar, motion, explicit 3D decision, responsive behavior, accessibility and performance constraints. Reuse project tokens through design-system. Extract principles from high-quality product, editorial or 21st.dev references when available; adapt them to the product rather than cloning.

Implement real content, functional controls, truthful data and clear loading, empty, error, disabled and success states. Choose visual intensity for the task: settings favor clarity, dashboards favor meaningful density, marketing may allow expression. Three.js, React Three Fiber, WebGL, shaders, Motion, scroll-linked animation, interactive lighting and layered composition are optional tools; use motion-ui or 3d-ui only when they improve the experience.

Render the result and run taste. Automatically revise identified design failures, then re-render and review again. Check narrow/mobile and wide layouts, keyboard navigation, focus, contrast, labels, reduced motion and overflow; complete final visual verification. Do not claim completion from code alone. If browser rendering is unavailable, provide implementation evidence and explicitly leave visual verification unverified. Report the design decision, functional changes and checks.
